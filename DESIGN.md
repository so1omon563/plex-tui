# plex-tui Design

## Why this document exists

Most software accumulates a visual style over time.

This project should instead cultivate one deliberately.

The goal of plex-tui is not simply to be a capable terminal client for Plex.

It should feel like a carefully curated media catalog that happens to live in a terminal.

This document exists to preserve that intent.

It is not a list of rules.

It is a collection of principles.

When implementation details and these principles disagree, revisit the implementation before revisiting the principles.

---

# Media first.

The collection is the product.

The interface exists to reveal it, not compete with it.

Artwork should remain the strongest visual element.

Everything else earns its prominence.

---

# The interface should become quieter as attention narrows.

Browsing should feel expansive.

Selection should feel focused.

Playback should feel immediate.

As users move closer to a piece of media, the interface should reveal richer information while becoming visually simpler.

---

# Information unfolds.

Do not present every available fact at once.

Information should appear in the order that people naturally become curious.

Identity.

Context.

Playback.

Summary.

Details.

Technical information.

The interface should reward curiosity rather than demand attention.

---

# Empty space is intentional.

Whitespace is not unused space.

It establishes rhythm.

It separates ideas.

It gives artwork room to breathe.

Do not fill space simply because it exists.

---

# Structure should support, not announce itself.

Borders, pane titles, separators, and visual framing are tools.

They should clarify relationships.

They should never become the subject of the interface.

If removing decoration improves understanding, remove it.

---

# Every screen should tell one story.

A Library answers:

"Where am I?"

A Collection answers:

"What can I browse?"

A Media Item answers:

"What makes this worth watching?"

Technical information answers:

"Why does this behave the way it does?"

Every screen should have a primary purpose.

Everything else is supporting material.

---

# Design for rhythm.

Good terminal interfaces are not merely efficient.

They have cadence.

Movement through the application should feel calm, predictable, and continuous.

The eye should never need to search for the current point of focus.

---

# Craft over novelty.

This project is not trying to reinvent terminal interfaces.

It is trying to demonstrate that they can feel carefully composed.

Small improvements accumulated over time are preferred to dramatic redesigns.

The goal is not to impress.

The goal is to endure.
